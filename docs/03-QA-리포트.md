## 화면 시나리오 (헤드리스 Chrome + 봇)
- 2인 원작 / 3인 11×11 / 4인 팀전 / 빠른 게임을 끝까지 진행 — 콘솔 오류 없음
- 확인: 갈 수 있는 칸 표시, 카드 선택 시 경로·목적지 강조, 기사 대상 칸(빨간 원·방패), 왕관 이동·돌 낙하·뒤집기 애니메이션, 결과 화면(영역 분해 "5²+4²+…", 동점 기사 규칙), 보드 보기 토글, 390px 폭

## 발견 → 수정
| # | 문제 | 수정 |
|---|---|---|
| 1 | 11×11 이상에서 보드가 9칸으로 잘려 보임 (CSS 변수 `--n`이 프레임에서 9로 덮어써짐) | 프레임의 기본값 제거, 게임 루트의 보드 크기를 그대로 사용 |
| 2 | 휴대폰에서 내 카드가 플레이어 목록·돌 공급 아래로 밀려 스크롤해야 보임 | 좁은 화면에선 보드 바로 아래에 내 카드 |
| 3 | 4인에 원작 카드 24장이면 손패 20장 후 더미 4장뿐 | 검증을 "카드 ≥ 인원 × (손패 + 2)"로 강화 |
| 4 | 돌 추천 버튼이 프리셋 값에도 항상 떠서 시끄러움 | 추천값과 12% 이상 차이날 때만 표시 |

## 알려진 제한
- 재배포 시 진행 중 게임 소실(메모리 단일 파드)
- 실기기(iOS Safari/안드로이드) 미확인 — 헤드리스 Chrome 390px 에뮬레이션으로만 확인

## 후속 반영 (같은 날)
| 요청 | 반영 |
|---|---|
| 무중단 배포 | RollingUpdate + 방 상태 넘겨받기(my-lost-city와 같은 방식). 로컬에서 서버 2개 + 프록시로 "게임 중 이전 서버 종료 → 브라우저·봇이 새 서버로 자동 재접속, 보드 그대로 이어서 진행" 확인 |
| 막힌 칸이 다크 모드에서 안 보임 | 라이트/다크 모두 빨간 빗금 |
| 왕관 크기 | 칸의 78% → 60% |
| 반응형 | 게임 화면을 기기 높이에 고정, 보드는 남은 공간에 맞춰 최대(컨테이너 쿼리), 정보 패널만 스크롤, 좁거나 세로면 아래로. 1440×900 / 1024×768 / 768×1024 / 390×844 / 360×640 / 844×390에서 페이지 스크롤 0 확인 |
| 남은 돌 경고 | 패널 상단에 눈에 띄게 (인원 수 이하면 빨간색·깜빡임) |
| 첫 화면 | 시연 보드 + 소개, '새 방 만들기'와 '초대받은 방 들어가기'를 색·아이콘이 다른 카드로 분리 |
| 게임 방법 | 9개 섹션 모달, 실제 부품 그림 + 플레이 영상, 첫 화면·로비·게임에서 열기 |
| my-lost-city에서 이식 | 방장 게임 중지 → 설정 변경 → 이어서 하기, 무중단 배포 방식, 카드 끌어다 놓기 |
| 감정 표현 | 줴줴이야, 🍵 티배깅 애니메이션 등 약올리기 |
| 시연 영상 | `npm run media`: 2배 픽셀 스크린샷 연속 촬영(CDP screencast는 CSS 픽셀로만 와서 흐렸음), GIF 256색·sierra 디더 |
